Lesson 0: Pipeline Basics

Orientation

Why are we learning this? Before we can build the self-improving loop (eval → diagnose → improve → optimize), we need a pipeline that actually runs end-to-end. Right now you can chunk a book and store it in Chroma. But you can't ask a question and get a scored answer. The agents need a working pipeline to orchestrate.

How does it work? Four steps in sequence: find the right pages → glue them together → read and answer → grade the answer.

Input → Output: A question string → an answer string + a quality score (0.0 to 1.0).

What breaks without it? The self-improving loop has nothing to evaluate. You can't diagnose a pipeline that doesn't run.

Step 2: Context Assembly (context_assembly.py)

Context card:

What it isPack retrieved chunks into one string within the LLM's token budget
Problem solved"How much of the retrieved context can the LLM actually read?"
Input → Output[chunk1, chunk2, chunk3] → "chunk1\n\nchunk2\n\nchunk3" (≤4000 tokens)
OwnsToken counting (tiktoken), greedy fill by score, truncation
Does NOT ownRetrieval, generation, evaluation
# assemble_context(chunks, max_tokens=4000)
# BEFORE:  [
#   {"text": "Embeddings map text...", "score": 0.87},  # 200 tokens
#   {"text": "Vector similarity...", "score": 0.72},     # 150 tokens
#   {"text": "The embedding model...", "score": 0.65}    # 180 tokens
# ]
# AFTER:   "Embeddings map text...\n\nVector similarity...\n\nThe embedding model..."
#          (530 tokens total — fits within 4000 budget, all 3 chunks included)

Greedy fill: Sort chunks by score (highest first). Add chunks one by one until adding the next would exceed max_tokens. Stop. This is the same pattern AutoRAG's compressor uses.

4. Quiz

  1. What are the four steps of the pipeline, in order?
  2. If retrieval returns 5 chunks but the context budget only fits 3, which 3 get included?
  3. What happens if the LLM generates an answer that isn't grounded in the context? Which metric catches it?
  4. Why do we need ground truth queries? What happens without them?
  5. If the unified score is 0.42, which step most likely failed? How would you debug it?
Reveal answers
  1. Retrieval → Context Assembly → Generation → Evaluation (scoring).
  2. The top 3 by score (highest first). The compressor uses greedy fill: sort by score, add until budget is full.
  3. The faithfulness metric (LLM judge checks each claim against context). Score drops below 0.50 → veto fires.
  4. Ground truth lets us measure correctness (answer vs expected answer). Without it, we can still measure faithfulness and relevance, but not whether the answer is actually right.
  5. Most likely retrieval (wrong chunks retrieved) or generation (LLM hallucinated). Debug: check retrieved_chunks scores, check if context contains the answer, check faithfulness score.
